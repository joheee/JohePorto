# johePorto: Core Context

Personal portfolio site. Next.js (App Router, TypeScript, Tailwind) on Vercel, Firebase (Firestore + Auth) as the backend.
All public content (name, hero, bio, skills, experience, education, projects) lives in Firestore and is edited from a private admin. The same data generates an ATS-friendly resume PDF.

- **Live:** https://www.johe.my.id (custom domain; the apex `johe.my.id` redirects to `www`, and `johedotcom.vercel.app` still works and canonicalises to `www`). Vercel project `johedotcom`.
- **Firebase project:** `joheportobackend` (one project shared by local dev and production: same data, same rules)
- **Repo:** github.com/joheee/JohePorto, branch `main`
- **Read first:** `AGENTS.md`. This is Next.js 16: APIs differ from older versions. Read the relevant guide in `node_modules/next/dist/docs/` before writing code.

## Firestore data model

**`settings/profile`** (single document, the whole public profile)
`name`, `roles[]` (rotating hero line), `pitch`, `email`, `location`, `status`, `focus` ("Now" tile), `bio[]` (paragraphs), `skillGroups[{name, items[{name, aliases[]}]}]` (the skill catalog, edited in Settings > Skills) with a derived flat `skills[]` (names only, never edited; a profile that only has legacy `skills` shows them as one group "Skills"), `socials[{label,href}]`, `experience[]`, `education[]`, `updatedAt`.
Each `experience` item: `role`, `company`, `summary` (lines starting with `•` or `-` render as bullets), `location` (optional, shown after the company; older entries have none), `stack[]` (technologies, shown as chips under the entry; older entries have none), `current` (bool), `startMonth`, `startYear`, `endMonth|null`, `endYear|null`, `createdAt` (Firestore **Timestamp**, kept on edit, stamped when an entry is first saved). Sorted on the site LinkedIn-style: current roles first, then by end date, then start date. Experience is a free-order array in the admin; sorting is display-only.
Each `education` item: `school`, `degree`, `location` (optional), `summary` (same bullet formatting, e.g. GPA), `current`, start/end month+year like experience. Shown on the site as a second timeline under Experience (newest first, same sorter); edited in Settings > Education. Older profiles without the field load as `[]`.
Skills catalog rules (`lib/skills.ts`, pure): names match on a normalised key (lowercase, letters/digits/`+`/`#` only), so React JS = ReactJS = react.js; real synonyms use `aliases` (Go / Golang). A spelling can belong to one skill only (validated). Job and project `stack` chips suggest catalog skills while typing (`ChipsInput` `suggest`/`resolve`). Settings > Skills shows a tray of stack names not in any group (add one by one or all at once) and spelling variants. **Saving the profile rewrites every job stack and every project stack to the catalog spelling** (project `updatedAt` untouched); `saveProject` does the same for that project. Group order is the array order (Settings > Skills has Up/Down buttons per group, keyboard- and screen-reader-friendly); it drives the public tile and the resume. The public About tile shows the groups (no heading when there is only one group).
Fallback: if the document is missing/invalid the site shows placeholder content from `src/lib/content.ts` (`defaultProfile`).

**`projects/{slug}`** (document ID = slug, immutable)
`title`, `summary`, `description` (same bullet formatting), `stack[]`, `links[{label,href}]` (**at least one required when saving**; older projects with none still load and show one blank row to fill in), **`month`, `year`** (manual "Created" date, required), `updatedAt`.
Shown **oldest first** by month/year, ties by title. No `order` field any more.
Legacy: a project saved before month/year existed (currently `postgresql-physical-backup-with-pgbackrest`, still has `order: 0`) falls back **at read time** to the month it was last saved (shows "Oct 2026"). Edit it in `/admin/projects` to set the real date.

**`messages/{id}`**: `name`, `email`, `text`, `read` (bool; missing = unread), `createdAt` (Timestamp). Written by the API route only.

**`posts/{id}`**: planned (`title`, `slug`, `content` Markdown, `tags`, `status`, `createdAt`). Rules already exist.

**Leftover junk from early open-rules tests, safe to delete in the console:** `posts/gnsBWLddPHkVuJapWb2C`, `projects/yY5zllSxhqxAYzSr5lAw`, `settings/main`. (The post would appear on the blog once it exists.)

**Current data state (end of this session, shared Firestore):** `settings/profile` has 6 experience entries (BINUS Teaching Assistant, BINUS Network Administrator, Paxel Indonesia, Virtue Digital Indonesia (renamed from Lacak.io, Tangerang), NobleProg, Kolosal AI), each with location and tech stack from the owner's `Resume_Johevin.pdf` (Kolosal AI has location only, no stack); 1 education entry (BINUS, GPA + Coobie bullet); **7 skill groups** (DevOps Tools, Languages, Backend Framework, Fullstack Framework, Frontend Framework, Database, Cloud; 44 skills; aliases: Go/Golang, Kubernetes/K8s, Bash Script/Bash, PostgreSQL/Postgres, React JS/React); 3 projects (AWS Base Infrastructure and GCP Base Infrastructure, May 2026, 2 bullets each; `postgresql-physical-backup-with-pgbackrest`, July 2026, one paragraph description), each with a GitHub link. ### Security rules (`firestore.rules`, must be published in the console by hand)
Owner = a single hard-coded UID. Public read: published posts, projects, settings. Public create-only on `messages` (field/size limits). Everything else owner-only. **The app itself uses the Admin SDK (bypasses rules)**, so rules protect against direct client access with the public web config.

## Architecture

**Reading data:** server components call `getProfile()` (`lib/settings.ts`), `getProjects()`/`getProject()` (`lib/projects.ts`), `getMessages()` (`lib/messages.ts`): Admin SDK, `server-only`, wrapped in React `cache`; `getProfile()` and `getProjects()` additionally cache the Firestore read across requests with `unstable_cache` (tag `site`, see Caching). Firestore Timestamps are converted to ISO strings before reaching client components.

**Writing data:** Server Actions in `src/app/admin/(protected)/actions.ts` (`saveProfile` (also rewrites job and project stacks to the catalog spelling), `saveProject`, `deleteProject`, `setMessageRead`, `deleteMessage`). Every action: re-checks the owner (`getAdmin()`), validates with `lib/validation.ts` (`parseProfile`, `parseProject`; server is the source of truth, forms also use native `required`), writes with the Admin SDK, then invalidates. Profile/project actions call `updateTag("site")` (clears the cached reads, read-your-writes) and `revalidatePath("/", "layout")` (rebuilds the static PDF/metadata routes); message actions only revalidate `/admin/messages` + `/admin`.

**Auth:** client signs in with Firebase Auth, posts the ID token to `/api/auth/session`, server verifies it (revocation check, UID === `ADMIN_UID`, sign-in < 5 min old) and sets an httpOnly session cookie that is valid for **3 hours from sign-in** (`SESSION_MAX_AGE_MS` in `lib/session-cookie.ts`; absolute, not extended by activity; Firebase signs the expiry into the cookie so the server enforces it). After that, admin pages redirect to `/admin/login` and a save returns "Not authorized. Please sign in again." (unsaved form edits are lost, so save before a long break). Cookies issued before a change keep their old expiry: sign out, or call `adminAuth().revokeRefreshTokens(uid)`, to cut them off. `lib/auth.ts`: `getAdmin()` / `requireAdmin()` verify the cookie on **every admin page and action** (layouts do not re-render on client navigation). `src/proxy.ts` (Next 16's middleware) is only an optimistic redirect for cookie-less visitors. Never rely on it alone.

**Caching:** pages render per request (CSP nonce, see Security headers); the Firestore reads are cached with `unstable_cache` (tag `site`) and cleared by `updateTag("site")` on saves. Saves made in the **production** admin therefore show immediately. Saves/writes from **local dev or scripts write to the same Firestore but cannot clear production's cache**: they show after the hourly refresh, the next deploy (the deploy id is part of the cache key) or a save in the prod admin. `/resume.pdf` is still static and rebuilt by `revalidatePath`.

**Validation limits** (see `lib/validation.ts`): name 80, pitch 300, bio 8x1500, skill groups 12 x skills 40 (name 40, aliases 8x40), roles 8x60, socials 10, experience 20 (summary 2000, role/company/location 100 single-line, stack 20x40), education 10 (school/degree/location 100, details 1000), projects: title 100, summary 200, description 3000, stack 20, links 10, slug `[a-z0-9-]` max 60.

**UI system:** dark/light via `data-theme` on `<html>` (inline script, no flash); tokens in `globals.css` (`--accent` indigo, etc.). Shared admin pieces: `fields.tsx`, `FormCard`, `ChipsInput`, `AutoTextarea` (auto-height, also used on the public contact form), `ConfirmDialog` (native `<dialog>`, replaces `confirm()`/`alert()` everywhere), `DateSelects` (month/year), `AdminNav` (active tab), `Icons`. `SettingsForm` and `ProjectForm` share the same pattern (single `form` state, `toPayload()` doubles as the dirty check, `saved` snapshot for Discard, `beforeunload` warning). Public: `Section`, `Reveal`/`TimelineItem` (motion), `FormattedText` (bullet lines), `ProjectCard` + `ProjectChips` + `ProjectLinks` (`components/ProjectCard.tsx`: the full project card, shared by the public section and the admin list; the first link is the filled main button; `footer` slot for admin actions; `ProjectChips` is also used by the Experience timeline), `PingDot`, `CopyEmail`, `MobileMenu`.

**Env vars** (`.env.example`; real values in `.env`, gitignored; same names set in Vercel Production):
`NEXT_PUBLIC_FIREBASE_*` (6 web-config values), `FIREBASE_SERVICE_ACCOUNT_KEY` (service-account JSON, one line, **no surrounding quotes in Vercel**), `ADMIN_UID`, optional `NEXT_PUBLIC_SITE_URL` (custom domain; otherwise `VERCEL_PROJECT_PRODUCTION_URL`, else localhost). `NEXT_PUBLIC_*` are baked in at build time: redeploy after changing them.

## Gotchas and decisions (learned the hard way)

**Vercel / Firebase**
- `firebase-admin` is pinned to **13.x**. v14 pulls `jwks-rsa` 4 -> ESM-only `jose` 6 loaded with `require()`, which crashed `/admin/login` on Vercel (`ERR_REQUIRE_ESM`) while working locally on Node 26. `engines.node` is 22.x; check the Vercel project's Node setting too.
- Missing `NEXT_PUBLIC_FIREBASE_*` at build time makes any page importing the client SDK 500 with `auth/invalid-api-key` (the home page does not import it, so it looked fine).
- Firestore `serverTimestamp()` cannot be used inside arrays: experience `createdAt` uses `Timestamp.fromDate`.
- Both environments share one Firestore: a schema change can break the *currently deployed* code reading the same documents. Deploy new code **before** saving data in the new format; when removing/renaming a field the old code requires, keep it until the deploy is live.
- Disable sign-ups in Firebase Auth settings (not verified done): the owner check is the UID, but open sign-up is unnecessary exposure.

**Next.js 16 / Tailwind 4**
- `middleware` is `proxy.ts`; `cookies()` is async; typed `LayoutProps<"/">` helpers (a type-check in a scratch copy fails with "Cannot find name 'LayoutProps'" until `next build`/`next dev` has generated them: not a real error); no `cacheComponents` here. Pages are now dynamic (nonce) with `unstable_cache` for data and `updateTag` in Server Actions; `revalidateTag` needs a second argument (`"max"`), `updateTag` is for Server Actions only. Static routes left: `/resume.pdf` (`force-static`), sitemap, robots, icons, OG images.
- Tailwind v4 `translate-*` uses the CSS `translate` property (not `transform`); `hover:` only applies on hover-capable devices (`@media (hover: hover)`); `transition-colors` also animates `outline-color`.
- Do **not** delete `.next` or run `next build` while the user's `npm run dev` is running (they share `.next`; the user runs dev on port 3000). Build in a scratch copy instead (copy `node_modules` for real: a symlinked one breaks Turbopack).
- Lenis' CSS sets `html`/`body` height to auto: use `min-h-dvh` (not `min-h-full`) on `<body>` so the footer sinks on short pages.
- iPhone browsers zoom into inputs under 16px: `globals.css` forces 16px for fields on `pointer: coarse` (unlayered rule so it beats utilities).
- `ghostButtonClass`/`buttonClass` set `inline-flex`, so `hidden` loses to it: hide them with `max-sm:hidden` (a variant), not `hidden sm:inline-flex`.
- The admin forms have a sticky save bar: `html` has `scroll-padding-bottom` so focused fields stay clear of it. In tests, scroll targets to the middle before clicking, or the bar swallows the click.
- The global `:focus-visible` outline must **not** set `border-radius` (it reshaped round pills while focused). (History: when project cards were a clickable button that opened a pop-up, the button had to hide its own ring and let the card draw one; the cards and the pop-up were removed on 2026-10-04, so that CSS is gone.) A control that fills its container must never draw a rectangular outline across rounded corners.
- A transformed child inside a scroll container (`overflow-y-auto`) flashes a scrollbar while it animates: animate the dialog itself (`dialog[open]` keyframes in `globals.css`), never its content.
- CSS grid columns need `minmax(0, 1fr)` or one long unbreakable line stretches the layout.
- `backdrop-filter` on the header makes `position: fixed` children relative to the header: use `absolute`.
- Hero button row: on phones two main buttons share a 2-column grid and the socials are an even `flex-1` row; from `sm` up both wrappers use `sm:contents` so everything sits in one row. The resume button reads "Resume" on phones and "Download resume" from `sm` (aria-label is always "Download resume"). The footer link list wraps (`flex-wrap`), because at 320px it overflowed by 5px.
- **Hero polish and cursor glow (2026-10-04):** `CursorGlow` (client, `components/motion/CursorGlow.tsx`, rendered once at the top of `app/page.tsx`, so public home only, not admin) is a **fixed, viewport-sized layer behind the whole page** (`-z-10`): one soft accent glow (`.cursor-glow` in `globals.css`, CSS drift animation, softer on the light theme than the dark one). With a fine pointer and no reduced motion, a rAF-eased `translate3d` moves it toward the cursor over every section (listener on `window`, transform only so no repaint); **touch devices (`@media (hover: none)`) get nothing at all: the layer is `display: none` (Tailwind `[@media(hover:none)]:hidden`), so no drift animation runs on phones**; reduced-motion desktop users get a static glow; without JavaScript it drifts (CSS). It rests at 70%/30% of the viewport. The opaque `bg-card` tiles cover it, so it shows in the gaps and margins (making cards slightly translucent would let it glow through; not done). The earlier hero grid was removed on request. Also in the hero: a "Currently <role> at <company>" line derived from the newest current job (`sortExperienceNewestFirst(...).find(e => e.current)`, nothing to edit), and stat numbers that count up in **pure CSS** (`@property --count` integer + `counter-reset`/`counter()` in `.count`; the real value stays in an `sr-only` span for screen readers and is the static fallback for reduced motion / no `@property`). **Do not put `.count` inside motion's `Reveal`**: inside its `opacity:0; transform` wrapper Chrome never redraws the changing counter text (it stayed at 0 although the computed value was right); the stats use the CSS `.rise` entrance instead.
- **Firebase client SDK must never reach the public bundle (regression found 2026-10-05):** after the shared navbar shipped, PageSpeed dropped (accessibility 100 -> 96, mobile best practices 100 -> 92, performance 99/96 -> 96/95). Cause: `SignOutButton` (rendered by `MobileMenu`/`AdminActions` in the navbar of **every** page) statically imported `@/lib/firebase`, so the home page downloaded the Firebase **Auth and Firestore** SDKs, and the SDK opened its auth iframe to `*.firebaseapp.com`, which the CSP (`default-src 'self'`) blocks: a console error plus a Chrome "Issues" entry (both scored in best practices, mobile run only). Fix: `SignOutButton` imports `firebase/auth` and `@/lib/firebase` inside the click handler. Only `SignOutButton` and `LoginForm` may import `@/lib/firebase`, and `LoginForm` is only on `/admin/login`. Regression test in `SignOutButton.test.tsx`. **How to check:** `puppeteer` request log on `/` must show no `firebase`/`googleapis` URLs and no iframes; or run Lighthouse locally (`npm i lighthouse` in the scratchpad, `--only-categories=accessibility,best-practices`, `--preset=desktop` for desktop): the local dev run reproduced the PageSpeed scores exactly, so it is a reliable way to find causes (the `valid-source-maps` audit always fails on dev/Next and is not weighted).
- **Contrast on the terminal:** the title "infra ~ zsh" was `text-zinc-500` on the near-black card (3.8:1, needs 4.5:1): now `text-zinc-400`. `aria-hidden` does not exempt text from the contrast audit. All text colors inside `InfraConsole` must pass 4.5:1 against `#0b0d12`.
- **Textarea height in the editor modal (fixed 2026-10-05):** `AutoTextarea` measured itself once on mount. In the site editor the form mounts inside the *closed* `<dialog>` (`display: none`, so `scrollHeight` reads 0) and the box stayed at `0px` until you typed (Pitch, Bio, Now looked "swallowed"). `next dev` hid it: React Strict Mode runs the layout effect a second time after the dialog has opened; production does not. Fix: a `ResizeObserver` re-measures whenever the box's width changes (hidden to visible, wrapping, font swap, container resize; it ignores its own height changes), replacing the old window-resize listener. Regression tests in `AutoTextarea.test.tsx`. Reproduce this kind of bug with a probe page that mounts the component in a closed dialog and then opens it (dev-only masking: check what Strict Mode double-invoking hides).
- Hero entrance is CSS (`.rise`), not motion, so text paints before JS loads (LCP). Keep above-the-fold content visible in server HTML.

**This session's learnings**
- The Settings save also rewrites every project's `stack` (batch update, `updatedAt` untouched because legacy projects borrow it as their date).
- `ChipsInput` suggestion list: choose with `onMouseDown` + `preventDefault`, otherwise the input's `onBlur` commits the half-typed text first.
- In scratch scripts: `require("firebase-admin/app")` with an absolute path fails (exports map): use `module.createRequire("<project>/package.json")`; `process.loadEnvFile(".env")` replaces dotenv; `puppeteer-core` lives in the scratchpad's own `node_modules`; `tsx` via `npx tsx` runs project TypeScript (e.g. `lib/validation.ts`, `lib/skills.ts`).
- Two elements now have `role="status"` on the settings page (the save message and the screen-reader announcer for skill-group moves). Test scripts that read the first `[role=status]` get the empty announcer: read all of them.
- Never `pkill -f "<text that is also in my own command>"`: it kills the tool's shell. Kill by PID from `ss -ltnp` instead.
- A mocked server-action response (`0:{...}\n1:{"ok":true}`) lets a test click Save without writing data; remove the interception for tests that must really save (and restore the value afterwards).
- Element screenshots of tall cards show the sticky header/save bar painted over them: that is an artifact, not a bug. In puppeteer, element/clip screenshots of just-animated content can come out blank: use a full-viewport screenshot, or pass `captureBeyondViewport: false` with `clip`. `getComputedStyle(el, '::before').content` returns `counter(...)`, not the number: judge CSS counters by screenshots.
- `unstable_cache` stays supported without `cacheComponents` (docs call it replaced by `use cache`): never let the cached function swallow errors, or a transient Firestore failure gets cached for an hour. Writing straight to Firestore from a script leaves the app's cache stale until the next real save (a test showed exactly this): after such a write, make a save in the admin or wait.
- A CSP that blocks `<style>` in dev only: Turbopack injects un-nonced `<style>` tags, so dev uses `style-src 'self' 'unsafe-inline'`.
- To test CSP semantics without the app: serve a tiny page with the policy from `buildCsp()` and try reflected `<script>`, `onerror=`, `javascript:` and `srcdoc` payloads.

## Security headers
Plain headers live in `next.config.ts` `headers()` (all paths): `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (camera, microphone, geolocation, payment, usb, browsing-topics off; clipboard stays on for the copy-email button). HSTS comes from Vercel. securityheaders.com: A. Mozilla Observatory's only deduction was `'unsafe-inline'` in `script-src`, which is now **removed**.

**CSP is nonce-based** (`src/lib/csp.ts` builds it, `src/proxy.ts` sets it with a fresh nonce on every page request): `script-src 'self' 'nonce-X' 'strict-dynamic'`, `style-src 'self' 'nonce-X'`, `style-src-attr 'unsafe-inline'` (inline `style=` attributes from motion and the hero cannot take a nonce; this is the one remaining relaxation), `default-src 'self'`, `img-src 'self' data: blob:`, `font-src 'self'`, `connect-src 'self'` + `identitytoolkit.googleapis.com`, `securetoken.googleapis.com`, `www.googleapis.com` (Firebase Auth on the login form), `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`, `upgrade-insecure-requests` (production only). Dev: `'unsafe-eval'`, `ws:`/`http://localhost:*`, and `style-src 'self' 'unsafe-inline'` (Turbopack injects un-nonced `<style>` tags). The proxy `matcher` skips `/api`, `_next/*`, `/resume.pdf` (a CSP on a PDF can stop Chrome's viewer), robots, sitemap, icons and OG images, and link prefetches. `RootLayout` is `async`, reads `x-nonce` from `headers()` and puts it on the theme `<script>`; **reading request headers there is what makes every page dynamic**. Next adds the nonce to its own scripts automatically. The JSON-LD block is not executable, so it needs none.

**Why not the alternatives:** `'unsafe-inline'` (the old policy) fails Observatory; experimental SRI + strict `script-src` was tried and **breaks the app** (Next emits ~26 inline `self.__next_f.push(...)` scripts per page that SRI cannot cover: no hydration); hashing inline scripts is impractical (their content includes page data and changes per build). Nonces were the only route.

**Cost and how it is kept cheap (shipped in `c95a48d`):** pages are no longer static/CDN-cached (`/` and the admin show as `ƒ` in the build output); only the PDF, sitemap, robots and icons stay static. To avoid a Firestore round trip per view, `getProfile()`/`getProjects()` wrap their Firestore read in `unstable_cache` (tag `site`, `revalidate: 3600`, key includes `VERCEL_GIT_COMMIT_SHA` so a deploy starts with a fresh cache). A failed read throws inside the cached function, so a failure is never cached (the outer `cache()` wrapper falls back to placeholders/`[]`). **`guard()` in `actions.ts` calls `updateTag("site")` + `revalidatePath("/", "layout")`** on profile/project saves, so a save shows on the site and rebuilds the PDF at once. Caveat (same as before): writes made outside the production app (local dev, scripts) do not clear production's cache; they show after an hour, or after the next deploy, or the next save in the production admin. Measured locally on production builds (Lighthouse, mobile/desktop): static 97/100, nonce 98/100, TTFB 3ms vs 10ms; **this excludes Vercel's function/network overhead, so expect a somewhat higher real TTFB than the old CDN-served static HTML** (re-run PageSpeed after deploying and compare with the earlier 96 mobile / 99 desktop; if it drops a lot, revert the commit to get static pages back).

Verified in a browser on production builds and in dev: zero CSP violations on the home page (scroll, theme toggle, project modal), login (a failed sign-in reaches Firebase and shows the normal error) and the admin pages; an external script, host and fetch are blocked. Against the same policy, markup-injection attacks are blocked while the trusted nonced script still runs: reflected `<script>`, `onerror=` handlers, `javascript:` links, a guessed nonce, `srcdoc` iframes. (`'strict-dynamic'` deliberately lets already-trusted code create scripts through DOM APIs, so a test that injects from the DevTools console/CDP will "succeed": that is not a hole, it is how the keyword works.) **If you add a third-party script, image host, font, embed or analytics, add its origin to the matching directive in `lib/csp.ts` (and give any inline script the nonce) or it will be blocked.** Changes to `next.config.ts` and `proxy.ts` need a dev-server restart.
